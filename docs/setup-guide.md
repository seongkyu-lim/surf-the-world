# 구축 가이드: Claude로 나만의 데일리 브리핑 사이트 만들기

매일 아침 Claude가 뉴스를 찾아 읽고, 브리핑을 써서, GitHub Pages 사이트에 올리게 하는 방법이다. 서버가 필요 없고, 한 번 만들어 두면 손댈 일이 거의 없다.

코드를 몰라도 따라 할 수 있게 썼다. 준비부터 첫 브리핑까지 30분 안팎이다.

## 전체 구조

```text
매일 아침 (예약 작업)
   │
   ▼
Claude 새 세션 시작
   │  1. 저장소 클론
   │  2. BRIEFING_GUIDE.md, SOURCES.md 읽기   ← 형식과 출처 기준
   │  3. tracking.md, 최근 브리핑 읽기        ← 어제와 이어지게
   │  4. 웹 검색으로 기사·공식 발표 수집
   │  5. _posts/오늘날짜-briefing.md 작성
   │  6. tracking.md, glossary.md 갱신
   ▼
git push → GitHub Pages가 자동으로 사이트 다시 빌드
```

핵심은 세 가지다.

- **규칙은 파일에 둔다.** 예약 작업 프롬프트는 짧게 두고, 형식과 품질 기준은 저장소 파일(`BRIEFING_GUIDE.md`, `SOURCES.md`)에 쓴다. 고치기 쉽고 변경 이력이 남는다.
- **기억은 저장소에 둔다.** 예약 작업은 매번 기억 없이 시작한다. `tracking.md`(진행 중인 이슈)와 지난 브리핑을 읽게 해서 연속성을 만든다.
- **출처에 등급을 둔다.** 발표 기관 원문을 먼저 찾게 하고, 쓰지 않을 출처를 명시한다. 이것이 없으면 검색 상위에 뜨는 블로그나 재가공 기사가 섞인다.

## 준비물

- Claude 유료 플랜 (웹 검색, 예약 작업, GitHub 연결을 쓸 수 있어야 한다)
- GitHub 계정

## 1단계: 저장소 만들기

1. GitHub에서 새 저장소를 만든다. **Public**으로, 아무 파일도 추가하지 않은 빈 상태로 둔다.
2. 저장소 이름은 자유. 사이트 주소는 `https://<아이디>.github.io/<저장소이름>/`이 된다.

무료 플랜의 GitHub Pages는 공개 저장소에서만 동작한다. 브리핑은 누구나 볼 수 있으니 개인 정보가 들어가지 않게 한다.

## 2단계: Claude에 GitHub 연결하기

claude.ai 설정의 커넥터에서 GitHub를 연결하고, 방금 만든 저장소에 접근을 허용한다. 쓰기 권한이 있어야 Claude가 푸시할 수 있다.

## 3단계: 프로젝트를 만들고 관심 분야 적기

claude.ai에서 프로젝트를 만들고 설명란에 관심 분야를 적는다. 예시는 [프롬프트 모음](prompts.md#1-프로젝트-설명-관심-분야)에 있다.

## 4단계: Claude에게 구축 맡기기

프로젝트 안에서 대화를 열고 저장소 주소와 함께 요청한다. [프롬프트 모음](prompts.md)의 2~4번을 순서대로 쓰면 된다.

이 저장소를 그대로 가져다 쓰고 싶다면 더 간단하다.

```text
https://github.com/seongkyu-lim/surf-the-world 저장소 구조를 참고해서
내 저장소 https://github.com/<아이디>/<저장소> 에 같은 방식의 데일리 브리핑 사이트를 만들어 줘.
관심 분야는 프로젝트 설명에 적어 뒀어. 매일 오전 7시에 발행되게 예약 작업도 등록해 줘.
```

Claude가 만드는 파일은 다음과 같다.

| 파일 | 역할 |
|---|---|
| `_config.yml`, `_layouts/`, `assets/style.css`, `index.html` | 사이트 뼈대 (Jekyll) |
| `BRIEFING_GUIDE.md` | 브리핑 형식, 요일 코너, 품질 규칙, 발행 전 점검 |
| `SOURCES.md` | 출처 등급과 제외 목록 |
| `CLAUDE.md` | 저장소를 연 Claude가 자동으로 읽는 안내문 |
| `tracking.md` | 진행 중인 이슈와 다음 일정 |
| `glossary.md` | 용어집 |
| `_posts/YYYY-MM-DD-briefing.md` | 하루 한 편의 브리핑 |

## 5단계: GitHub Pages 켜기

Claude가 첫 푸시를 한 뒤 한 번만 하면 된다.

1. 저장소의 **Settings → Pages**로 간다.
2. **Source**를 "Deploy from a branch"로 두고, **Branch**를 `main`, 폴더를 `/ (root)`로 고른 뒤 Save.
3. 1~2분 뒤 `https://<아이디>.github.io/<저장소이름>/`에 접속해 확인한다.

저장소 이름이 `<아이디>.github.io`이면 이 단계 없이 자동으로 켜진다.

다른 저장소 이름을 쓴다면 `_config.yml`의 `url`과 `baseurl`이 자기 주소와 맞는지 확인한다. 맞지 않으면 CSS가 깨져 보인다.

```yaml
url: https://<아이디>.github.io
baseurl: /<저장소이름>
```

## 6단계: 예약 작업 등록

Claude에게 "매일 오전 7시에 브리핑이 발행되게 예약해 줘"라고 요청한다. 등록되는 프롬프트는 [프롬프트 모음 5번](prompts.md#5-매일-실행되는-예약-작업-프롬프트)과 같다.

확인할 것:

- **승인 설정**: 예약 작업이 실행 중 승인을 기다리면 아무도 눌러 주지 않아 멈춘다. 작업 설정에서 자동 승인을 켤 수 있는지 확인한다.
- **첫 실행 점검**: 등록한 다음 날 사이트에 새 글이 올라왔는지 본다. 올라오지 않았다면 예약 작업의 실행 기록에서 어디서 멈췄는지 확인한다.

## 운영하면서

- **형식 고치기**: 브리핑이 길다, 어떤 코너가 필요 없다 싶으면 Claude에게 "작성 규칙을 이렇게 고쳐 줘"라고 한다. `BRIEFING_GUIDE.md`가 바뀌면 다음 날부터 반영된다.
- **출처 다듬기**: 숫자가 틀린 매체를 발견하면 `SOURCES.md`의 제외 목록에 넣는다.
- **틀린 내용 고치기**: 해당 날짜의 `_posts/` 파일을 고치고 푸시한다. GitHub에서 직접 편집해도 된다.

## 알아 둘 한계

- AI 요약이라 오류가 있을 수 있다. 출처 등급과 발행 전 점검으로 줄이지만 없애지는 못한다. 돈이 걸린 결정은 원문을 확인한다.
- 일부 사이트(유료 매체, 자동 접근을 막은 사이트)는 Claude가 본문을 읽지 못한다. 이때는 그 발표를 전한 다른 매체로 대신한다.
- 웹 검색 결과에 따라 날마다 품질이 조금씩 다르다. 쓸 만한 기사가 적은 날은 억지로 채우지 않고 짧게 내도록 규칙을 뒀다.
- 정치 쟁점은 양쪽 입장을 나란히 싣게 했지만, 어떤 기사를 고르느냐에서 치우침이 생길 수 있다.

## 응용

- **다른 주제**: `BRIEFING_GUIDE.md`의 관심 분야 표와 요일 코너만 바꾸면 육아, 업계 동향, 해외 취업 등 어떤 주제로도 쓸 수 있다.
- **알림**: 사이트에는 RSS(`/feed.xml`)가 있다. RSS 리더나 메일 전달 서비스에 연결하면 발행될 때 알림을 받을 수 있다.
- **주간 요약만**: 예약 일정을 주 1회로 바꾸고 일요일 형식만 쓴다.
